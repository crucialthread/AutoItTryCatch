TryCatchLint - Static Analysis Tool

TryCatchLint is a static analysis tool that checks .au3 files for common TryCatch usage mistakes before they reach runtime. It integrates with SciTE's Tools menu and can also be run from the command line.

What It Checks

Check 1 - Unbalanced _Try()/_EndTry() calls

Every _Try() must have a corresponding _EndTry(). Failing to close a try scope corrupts the internal depth counter and causes unpredictable behavior at runtime. TryCatchLint detects this at the per-function level, so an imbalance in one function does not mask an imbalance in another.

The early-return pattern (Return _EndTry() or _EndTry() followed by Return value) is correctly accounted for - a Return inside an open try scope is counted as requiring its own _EndTry(), so valid early-return code is not flagged as unbalanced.

Check 2 - Unregistered exception name references

Exception names passed as literal strings to _ThrowException() or _Catch() are compared against names registered via _RegisterException() in the same file. Any name not found in the registry is reported as a warning - it is likely a typo, or the exception relies on auto-registration (which is allowed but should be used with care).

Running from the Command Line

TryCatchLint can be run directly from any command line, independently of SciTE:

AutoIt3.exe TryCatchLint.au3 "C:\path\to\script.au3"

Output lines use the exact Au3Check error format that SciTE recognizes:

"C:\path\to\script.au3"(14,1) : error: Unbalanced _Try()/_EndTry()...
"C:\path\to\script.au3"(22,1) : warning: 'TypoException' is not registered...

Exit codes:

0No issues found.
2One or more errors found. Matches Au3Check's own exit code convention.

This makes TryCatchLint usable as a pass/fail gate in build scripts or CI pipelines.

SciTE Integration

The installer registers TryCatchLint as a SciTE Tools menu command automatically. Once registered, it is available as TryCatch Lint in the Tools menu (default shortcut: Ctrl+Alt+L).

Running it from SciTE works exactly like Go/Build - output appears in the console pane using the Au3Check error format, so SciTE inline-highlights the offending line and automatically jumps to the first finding.

Self-Registration

If you installed the core libraries manually (without using the installer), you can register the lint tool in SciTE by opening TryCatchLint.au3 directly in SciTE and pressing F5/Go with no arguments. This triggers the self-registration flow, which:

  • Detects whether TryCatch Lint is already registered in SciTEUser.properties
  • Finds the next available Tools menu slot (minimum slot 40, per SciTE convention)
  • Writes the registration block to SciTEUser.properties
  • Prompts you to restart SciTE for the change to take effect

Running self-registration on an already-registered installation offers to overwrite the existing entry - useful after moving the installation to a different path.

Known Limitations

TryCatchLint is a text-based scanner, not a real AutoIt parser. It operates on raw source lines using regular expressions and has the following known limitations:

No #include following Only the file being linted is scanned. Exception names registered in included files are not visible to Check 2, so references to them may be reported as warnings even if correct.
Line continuation Calls split across multiple lines using the _ continuation character may not be detected correctly.
String literals Try/catch-looking text inside string literals (e.g. in test headers) is correctly ignored - string contents are stripped before pattern matching for Check 1.
Block comments #cs/#ce block comments are correctly ignored, with line numbers preserved accurately after removal.

Treat TryCatchLint findings as strong hints rather than guarantees. False positives are possible in unusual formatting scenarios.
